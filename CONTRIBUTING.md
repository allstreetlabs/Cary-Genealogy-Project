# Contributing

Relatives, historians and other researchers are welcome. You need not prove a link to the family to suggest a correction.

1. Search existing people, claims, sources and questions before adding anything.
2. Use a public issue for a non-sensitive lead, or propose file changes in a pull request.
3. Give the affected IDs, exact proposition, full citation/record locator, what you personally examined, and what remains uncertain.
4. Explain whether information is firsthand recollection, inherited testimony, a document transcription, published genealogy or inference. Preserve conflicting accounts.
5. Add only public-cleared content. Do not post living people's personal information, DNA results, unredacted certificates, emails, confidential correspondence or family pictures without permission. This includes issue text, PRs and commit history.
6. A research editor reviews identity, source dependence, conflicting evidence and publication clearance. Accepted changes are reconciled with HQ before an approved public edition is released.

Use temporary `PROPOSED-...` labels in discussions for new entities. Maintainers allocate permanent IDs through HQ; do not create competing P/S/C/L registers. Never recycle retired IDs. Contributions are credited only with the contributor's consent.

If your evidence is private, post only a generic note that private evidence exists and request a secure intake route. No such route is configured yet; do not attach it to the public issue while waiting.

Changes to a fact must update its claim, source and human-readable summary together. A successful automated check is not approval. Maintainers should not merge their own substantive historical claim without another qualified review once a second editor is available; exceptions need an explicit recorded reason, not a false assertion of independent review.
